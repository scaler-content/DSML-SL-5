What is an ensemble?

Ask five different colleagues to estimate how many riders Orbit Express will need next month and you will get five different numbers. Average those five guesses and the result is often more accurate than any single person's guess. That is the "wisdom of the crowd", and it is the core idea behind every ensemble method.

Combine several models, none of which needs to be perfect on its own, so that the combined prediction is more accurate and more stable than any single one.

Bagging: Bootstrap Aggregating

The name describes the recipe. Bagging is Bootstrap AGGregatING.

  1. Bootstrap. Create many random samples of the training data, each the same size as the original, drawn with replacement. The same row can appear more than once in a sample, and some rows will not appear at all.
  2. Aggregate. Train one model independently on each bootstrap sample, then combine their predictions: a majority vote for classification, an average for regression.

Bagging pipeline

Step through the recipe

Each individual tree still has high variance, exactly like the ones trained above. But because each tree sees a different random sample, their individual mistakes tend to be different too, and averaging cancels much of that noise.

On the real 1,848-row training set, a single bootstrap sample contained about 63.6% of the original rows (0.636). The remaining roughly 37% are left out for that particular tree. This is not a coincidence, and it turns out to be extremely useful (see the out-of-bag score below).

Where does 63% come from?

In a single draw, a specific row is not picked with probability 1 − 1/n. Across n draws, it is never picked with probability (1 − 1/n)n. As n grows this approaches 1/e ≈ 0.368, so about 1 − 0.368 = 0.632 of rows appear. The number barely changes with dataset size, which is what the simulator above shows.

Random Forest: Bagging, plus one more trick

Plain Bagging of decision trees already helps, but there is a subtle problem. If one feature is by far the strongest predictor (for example MaritalStatus_Single, which dominated feature importance for the single tree), then almost every bootstrapped tree will pick it for its very first split anyway.

The trees end up looking alike. Averaging similar, correlated models does not reduce variance nearly as much as averaging genuinely different ones.

Random Forest fixes this with one extra layer of randomness: at each split, instead of considering every feature, it considers only a random subset of them.

Row samplingFeature (column) sampling per split
Plain Bagging of treesYes (bootstrap)No, all features considered every time
Random ForestYes (bootstrap)Yes, only a random subset considered each time

First split of 12 trees: Bagging vs Random Forest

Simplified illustration

Each small grid shows a tree's first split: filled squares were considered, and the gold square with a border is the one chosen. The illustration assumes the strongest feature available always wins the split.

This forces different trees to rely on different features some of the time, which makes them less correlated with each other, which in turn makes their averaged prediction more stable.

The out-of-bag (OOB) score: validation almost for free

Each bootstrap sample leaves out roughly 37% of the original rows. Those leftover rows for a given tree are that tree's Out-of-Bag (OOB) samples. That tree never saw them during training, so they work exactly like a validation set, for free.

How the OOB score is calculated

For every single training row:

  1. Find every tree in the forest for which that row was out-of-bag (left out of its bootstrap sample).
  2. Get a prediction for that row from only those trees, combined by majority vote.
  3. Compare that combined prediction with the row's true label.

Average this across every training row and you get the OOB score: an honest estimate of test performance, without setting aside a separate validation set at all.

Close the loop on the earlier experiment. Instead of ten single trees, train ten Random Forests (each with a different random seed, 100 trees, max_depth=4) and compare the spread of their test accuracies with the single trees.

The Random Forest's box is noticeably narrower. Same underlying data, same depth setting per tree, but a visibly smaller spread, and a higher mean. This is Bagging's whole promise made concrete: lower variance, without a corresponding jump in bias, because averaging many decorrelated, low-bias trees keeps the low bias while cancelling out much of the individual noise.

Ticket update. There is now direct evidence that a Random Forest is more stable than a single tree, which is exactly what HR asked for.

Most look familiar from the decision tree, since a forest is built from trees. A few are specific to the ensemble itself, and are marked below.

Grid search: try every combination

GridSearchCV exhaustively tries every combination of the hyperparameter values you supply, evaluating each with cross-validation. It then refits the single best combination once more on the full dataset (refit=True by default). That makes the total number of .fit() calls larger than most people expect.

Grid search fit-count calculator

Edit the counts or load a preset

The notebook's grid is n_estimators × max_depth × criterion × bootstrap × max_features = 4 × 3 × 2 × 2 × 3 = 144 combinations, each cross-validated 3 times, plus one refit: 433 forests trained in total. It can take a while to run.

View the grid search code and output

params = {

    'max_depth': [3, 5, 10],
    'criterion': ['gini', 'entropy'],
    'bootstrap': [True, False],
    'max_features': [8, 9, 10]

                     cv=3,

print('Best params:', grid.best_params_)

Randomized search: sample instead of exhausting

When a hyperparameter is continuous (like ccp_alpha), trying every value is impossible. RandomizedSearchCV instead samples a fixed number of random combinations from distributions you specify. It is often nearly as good as a full grid search for a fraction of the compute.

In the notebook, the search starts from the grid search's own best configuration and tunes only ccp_alpha on top of it, sampled uniformly between 0 and 0.4 across 15 iterations with 3-fold cross-validation.

Grid searchRandomized search
StrategyTries every combination of listed valuesSamples a fixed number of combinations (n_iter)
Continuous valuesMust be discretised by handCan sample from a distribution
As hyperparameters growCost multiplies with every new oneScales better; cost is set by n_iter
Notebook resultBest score 0.901 (max_depth=10, max_features=8, n_estimators=200, bootstrap=True, criterion='gini')Best ccp_alpha ≈ 0.0596, best score 0.727

The randomized search's score is a fresh 3-fold cross-validation run, so it is not directly comparable with the grid search's 0.901. A different number here reflects re-running cross-validation on a different configuration search, not a regression in the model.

View the randomized search code and output 
from scipy.stats import uniform
from sklearn.model_selection import RandomizedSearchCV

params_dist = {'ccp_alpha': uniform(loc=0, scale=0.4)}  # sampled uniformly between 0 and 0.4

# Build directly on top of the grid search's own winner
best_rf_estimator = RandomForestClassifier(random_state=7, **grid.best_params_)

random_search = RandomizedSearchCV(
    estimator=best_rf_estimator,
    param_distributions=params_dist,
    scoring='accuracy',
    cv=3,
    n_iter=15,
    n_jobs=-1)

random_search.fit(X, y)

print('Best param:', random_search.best_params_)
print('Best score:', round(random_search.best_score_, 3))

Random Forest feature importance

With the tuned configuration fitted on the full data, a forest reports how much each feature contributed to its splits.

Feature importance in a forest is averaged across every tree, so it tends to be more stable and trustworthy than a single tree's version, for exactly the same reason the predictions themselves are more stable. Comparing the forest's ranking with the single tree's ranking is a good way to see how much a single tree's explanation can depend on the sample it happened to see.

View the feature importance code 
best_rf = RandomForestClassifier(random_state=7, **grid.best_params_)
best_rf.fit(X, y)

importances = best_rf.feature_importances_
indices = np.argsort(importances)[::-1]
names = [X.columns[i] for i in indices]

plt.figure(figsize=(15, 6))
plt.bar(range(X.shape[1]), importances[indices])
plt.xticks(range(X.shape[1]), names, rotation=90)
plt.title('Random Forest Feature Importance')
plt.tight_layout()
plt.show()

Explaining it in plain language. A single tree is one person's opinion, shaped by the exact records it saw. A forest is the averaged judgement of many trees, each trained on a different sample, so its answers, and its explanation of what matters, change far less when the data shifts slightly.

Summary

Ensembles

An ensemble combines several models so the group's prediction is more accurate and more stable than any single model. The four main families are Bagging, Boosting, Stacking and Voting.

Bagging

Bagging (Bootstrap Aggregating) trains many models independently on bootstrap samples, drawn with replacement, and combines them by majority vote or averaging. Any bootstrap sample contains roughly 63% of the original rows; the other roughly 37% are that tree's out-of-bag rows.

Random Forest

A Random Forest is Bagging of decision trees plus one more layer of randomness: only a random subset of features is considered at each split. This decorrelates the trees and improves how much variance the averaging removes.

The OOB score

Each tree's own leftover rows act as a built-in validation set, giving an honest performance estimate without setting aside separate validation data.

Measured variance reduction

Ten single trees on resampled data had a noticeably wider spread of test accuracy (std 0.026, mean 0.772) than ten differently-seeded Random Forests (std 0.011, mean 0.815).

Hyperparameters and tuning

Random Forest hyperparameters mostly mirror a single decision tree's, plus n_estimators, max_features and bootstrap, which control the ensemble itself. GridSearchCV exhaustively tries every combination; RandomizedSearchCV samples a fixed number of combinations, which scales better as hyperparameters multiply.

Feature importance

Importance from a forest is averaged across every tree, making it more stable than a single tree's importance.

Where this leads

Bagging builds many trees independently and lets them vote. What if, instead, each new tree was built specifically to fix the mistakes of the ones before it? That is the idea behind Boosting.
